# 角色档案

给同一只桌宠多个**互相独立**的角色：每个角色有自己的人设、记忆、会话、附件与 Git 历史；
在原生「装扮」页点击已绑定的外观，就切换到那个完整角色。

Coopanion 的非官方 Cortico World 纯扩展。不修改 Coopanion 安装文件、
内置依赖或原生前端；所有改动都落在扩展自己的部署目录与 `CORTICO_HOME` 下的角色目录里。

- 纯扩展：卸载扩展即可回到单角色，宿主文件一字节不动。
- 数据隔离：每个角色独立部署根 + 独立记忆/数据目录；原始角色已有的自定义路径原样保留。
- 天然共享：模型连接、已装扩展、语音模型文件（`providers/`、`models/`、`runtimes/`）跨角色共用。
- 无删除：停用与解绑外观都不会删掉角色档案。

## 功能

### 角色管理面板

高级模式 WebUI 的 World 页 →「角色档案」：

- 查看当前角色与全部角色，创建新角色（全新空白档案，模型连接共享）；
- 「人设（`CONSTITUTION.md`）」「用户认识（`PARTNER.md`）」专用编辑入口，普通笔记分开管理，
  文档支持中文子目录（如 `notes/trip.md`）；
- 保存冲突保护：别人或模型改过同一文档时不会静默覆盖，可载入最新内容合并或另存副本；
- 工作区有 Git 时每次保存自动生成一个版本，保存回执里给出提交号；
- 绑定 / 解除绑定外观（解绑只移除「点击切换」映射，不删角色档案与外观）；
- 排定切换、恢复原始角色、「切换状态」页查看事务与错误的人话说明。

### 原生装扮切换

在原生装扮页点击已绑定到某角色的外观，就切换到那个完整角色（切换会短暂重启伴侣）。
未绑定的外观、以及同一外观的配色/服装变化只执行普通换装。外观改绑给别的角色时，
面板会明确询问「绑定并立即切换」，避免「点了没反应」的歧义状态。

**一个外观同时只能属于一个角色**：改绑会解除原绑定，因此不会出现两个角色抢一个外观的来回弹。

### 数据隔离与恢复

- 每角色独立部署根 + 记忆/数据目录，切换不改写彼此内容；
- 启动失败自动回源：连续两次失败回到原始角色，并留下明确原因；
- 通过宿主角色 `memory`/`data` 路径进行的工具晚写仍归属**源**角色，不会写到新角色；
- 登记/迁移中断后保留完整副本，无法自动判定时停止切换并报告错误，而不是猜；
- 部署被其他进程占用时拒绝更改角色存储（实例锁门控）；
- 扩展被停用或处于「停用搁置」时跳过存储准备，一字节不写。

### 多角色协作接口

`./profile-api` 是给多角色共处包用的稳定接口（`PROFILE_PROTOCOL = 1`），import 时**没有**
bootstrap 副作用：

```js
import { createProfileService, waitForSingleMode, PROFILE_PROTOCOL } from 'cortico-world-character-profiles/profile-api';
```

提供能力协商、角色列表与快照、存储描述、人设文档读写与群聊共享、单/多人模式、
角色租约、外观归属写回，以及位置记忆移交。多人模式下单角色想重启会等待（`waitForSingleMode`）。

### 本机 DSH 桥接

角色开启 DSH 桥接时，扩展会跟随本机 DSH 的地址变化（仅回环地址、仅
`/coopanion/pet` 路径、无凭据）。地址改写只在旧地址探测失败、端口枚举**恰好唯一**命中、
且中途地址未被别的进程改过时发生。可用 `dshAutoDiscover` 关闭。

## 安装

需要 Windows 10 1809+ / Windows 11，以及支持 **World API 6** 的 Coopanion。

1. 取得本仓库源码目录（git clone 或下载解压）。安装入口只接受**目录**，不直接吃 `.tgz`。
2. 打开 Coopanion 的 WebUI →「扩展」页 → 安装 → 选择上面那个**目录**（含 `package.json`），
   确认后等待安装完成。安装走宿主的 `POST /api/extensions/install`，需要 `corepack`/`pnpm` 可用。
3. **重启 Coopanion**。
4. **首次启用**：扩展安装后默认**未启用**。在 WebUI 的世界/配置组里打开
   `worlds.character-profiles.enabled`（「角色档案」配置组 →「启用角色档案」），然后**再次重启**。
5. 首次启动后扩展自动登记「原始角色」，此后 WebUI 的 World 区出现「角色档案」页。

如果两步重启后仍看不到「角色档案」页，先确认第 4 步的开关确实是打开状态。

## 使用

1. 在「角色档案」页创建角色，可同时选择初始外观（同一外观只能绑一个角色，改绑会确认并解除原绑定）。
2. 打开原生「装扮」页，点击已绑定到某角色的外观 → 切换到该角色（重启一次伴侣）。
   若该外观正被当前角色穿着，请用面板的「切换」或「绑定并切换」。
3. 「人设」按钮进入文档列表：「人设」「用户认识」专用入口，或打开普通笔记；
   「切换状态」页查看切换事务与错误。

也可以直接对桌宠说，它有一个 `character` 工具：

| action | 作用 |
| --- | --- |
| `list` | 列出角色、当前角色、未完成事务 |
| `switch` | 切换角色（需要重启，当前对话中断） |
| `figure` | 为角色指定默认形象图；改绑别人的外观必须显式 `force: true` |

## 工作方式

```
原生装扮点击 / 面板操作 / character 工具
   → 写入切换事务（journal）
   → 重启伴侣进程
   → 新 Core 以目标角色的部署根与记忆/数据目录启动
   → 确认应用（confirmApplied），失败计数达两次则回源
```

- 切换＝重启伴侣：Core 会短暂离线，数据不丢，重启后的新会话即使用新角色的全部档案。
- 人设与用户认识会进模型的系统前缀；**保存后立即写盘，但当前进行中的对话不会中途换前缀**，
  需新会话或控制台的「前缀待重新载入」入口。其余 Markdown 是普通笔记，模型用文件工具按需读写。
- 角色注册表在 `<CORTICO_HOME>/roles/index.json`，活动指针为 `roles/active`，
  每个角色一个 `<CORTICO_HOME>/roles/<roleId>/companion/` 部署根，`.role-id` 标记归属。
- 新角色的记忆默认落在 `<role>/companion/workspace`、数据落在 `<role>/companion/data`
  （原生 Cormini 的缺省位置，避免指向新空目录而静默遗忘已有内容）。
- 外观资源在共享的 `<CORTICO_HOME>/figures/`，切换角色不会复制或改写外观。
- 多角色协作的控制面在 `<CORTICO_HOME>/character-profiles/runtime-ownership/`：
  `mode.json`、`mode-stop.json`、`<roleId>.lease.json`、`<roleId>.position-transfer.json`、`recovery/`。

## 能力边界

- 只做角色档案的**部署与切换**，不提供第二套模型调用、不提供 TTS、不改人格内容本身。
- 不隔离 DSH 等外部服务的会话；第三方工具若自行写入固定共享路径，不在角色目录隔离范围内。
- 切换必定重启伴侣，桌面窗口会短暂消失，这是宿主契约决定的，不是缺陷。
- 不提供删除角色：停用与解绑都不会删除角色档案，清理需用户自己操作目录。
- 「同一外观只绑一个角色」是刻意的约束；需要换角色请用改绑，不要期待一击两用。
- Electron 悬浮窗内的装扮页点击与浏览器版走同一 `/api/skin` 路径，但悬浮窗内点击
  未在真实用户实例上逐项操作过。
- 宿主升级可能带来破坏性契约变更；本扩展只使用公开 World 接口，声明 `api: 6`，
  不兼容的宿主会由安装器拒绝。
- 「连续两次启动失败自动回源」的逻辑仍在，但在较新的宿主上**难以复现**：宿主已改为
  某个 World 启动失败时跳过它并让 Core 照常启动（0.2.13 起），因此扩展通常观测不到
  「目标 Core 整体退出两次」。这条能力的实测状态见 CHANGELOG 的已知事项。

## 配置

配置入口在 World 页的「角色档案」配置组，写进宿主配置的 `worlds.character-profiles.*`：

| 键 | 类型 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `enabled` | boolean | `false` | 启用后本扩展接管多角色部署根；关闭则完全不动数据 |
| `dshAutoDiscover` | boolean | `false` | 角色开启 DSH 桥接时，自动跟随本机 DSH 地址变化 |

两项都**不是热更新**（`x-hot: false`），修改后需要重启进程。对应 `config.json` 片段：

```json
{
  "worlds": {
    "character-profiles": {
      "enabled": true,
      "dshAutoDiscover": false
    }
  }
}
```

面板与工具操作都走宿主公开接口，不需要手工编辑角色目录。手工修改 `roles/index.json`
可能在下次启动被规范化器纠正，不建议。

## 更新与回退

**本机目录安装**：宿主以 link 方式加载这个目录，不从 npm 查询更新。保留目录位置，替换成新版本
源码，运行类型检查，然后在 Coopanion 重启进程。角色数据由宿主保存在 `CORTICO_HOME` 下，
换版本不覆盖它。

**回退**：换回旧版本源码并重启即可。角色目录、注册表与 Git 历史都是纯数据，
不随扩展版本改变；因此降级一般安全。若新版本做过存储规范化，回退后建议先确认
`roles/index.json` 与各角色 `companion/config.json` 的 `paths` 仍指向预期目录。

## 开发与验证

无构建步骤：`src/*.ts` 由宿主以类型剥离直接加载，`webui/webui.js` 是免构建的自包含 ES module。

```bash
# 类型检查（strict + noUnusedLocals + noEmit）
npm install --no-save typescript@5.9 @types/node
npx tsc --noEmit -p .
```

本仓库只含扩展本体。真实 Core 隔离验证（G1/G2/G3）、面板 API、恢复矩阵、
浏览器 UI 闭环与安装/停用/升级回归都在独立的验证工作副本中进行，因此不随仓库分发。

已验证（针对当前 0.3.7 字节）：严格 TypeScript 干净；单元边界测试 31/31；
真实 Core 隔离 G1 36/36、G2 24/24、G3 16/16；面板 API 38/38；切换 8/8；
恢复矩阵 16/16；安装树 4932 个文件前后哈希一致。浏览器编辑器 10/10 与原生装扮 7/7
是更早版本轮次的结论，未在本版本重跑。
